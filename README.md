# endf-parserpy - an ENDF-6 toolkit for Python

[![PyPI version](https://img.shields.io/pypi/v/endf-parserpy)](https://pypi.org/project/endf-parserpy/)
[![Python versions](https://img.shields.io/pypi/pyversions/endf-parserpy)](https://pypi.org/project/endf-parserpy/)
[![Tests](https://github.com/IAEA-NDS/endf-parserpy/actions/workflows/test_package.yml/badge.svg)](https://github.com/IAEA-NDS/endf-parserpy/actions/workflows/test_package.yml)
[![Documentation](https://readthedocs.org/projects/endf-parserpy/badge/?version=latest)](https://endf-parserpy.readthedocs.io/en/latest/)

`endf-parserpy` is a Python package for reading
and writing [ENDF-6](https://doi.org/10.2172/2007538) files.
This functionality in combination with Python's
powerful facilities for data handling enables you to
perform various actions on ENDF-6 files, such as:

- Access any information easily
- Modify, delete, and insert data
- Perform format validation
- Convert to and from other file formats, such as JSON
- Merge data from multiple ENDF-6 files into a single file
- Read and write files containing multiple materials (tapes)
- Compare ENDF-6 files and generate meaningful reports of their differences
- Construct ENDF-6 files from scratch


Many of these actions can also be performed from the command line
through the `endf-cli` tool.

The support for the ENDF-6 format is comprehensive, and some special
NJOY2016 output formats are supported as well. The package has been
tested on the various sublibraries of the major nuclear data
libraries, such as
[ENDF/B](https://www.nndc.bnl.gov/endf/),
[JEFF](https://www.oecd-nea.org/dbdata/jeff/),
and [JENDL](https://wwwndc.jaea.go.jp/jendl/jendl.html).
Files that bundle several materials — including PENDF tapes
that repeat the same material at different temperatures — are
supported both as plain lists of materials and through a lazy,
memory-bounded `EndfFile` interface for large files.
Parsing and writing are heavily optimized; see
[Performance](#performance) below for concrete figures.


## Install endf-parserpy

This package is available on the
[Python Package Index](https://pypi.org/project/endf-parserpy/)
and can be installed using `pip`:

```sh
python -m pip install endf-parserpy --upgrade
```

The optional NumPy dependency, installed with
`python -m pip install "endf-parserpy[fast]"`, enables
`array_type="numpy"`, the fastest parsing mode, and a faster scan
of multi-material files. Without NumPy, a pure-Python fallback is used.

## Simple example

The following code snippet demonstrates
how to read an ENDF-6 file, change the
`AWR` variable in the MF3/MT1 section
and write the modified data to a new
ENDF-6 file:

```python
from endf_parserpy import EndfParserFactory
parser = EndfParserFactory.create()
# fastest variant, returning arrays of numbers as numpy arrays:
# parser = EndfParserFactory.create(array_type="numpy")
endf_dict = parser.parsefile('input.endf')
endf_dict[3][1]['AWR'] = 99.99
parser.writefile('output.endf', endf_dict)
```


## How it works

Support for the ENDF-6 format in `endf-parserpy` is not hand-coded
section by section. The format is described by *recipes*, written in a
formal language that mirrors the record layout of the
[ENDF-6 formats manual](https://doi.org/10.2172/2007538). This is the
complete recipe for an MF3 section (cross sections):

```
[MAT, 3, MT/ ZA, AWR, 0, 0, 0, 0] HEAD
[MAT, 3, MT/ QM, QI, 0, LR, NR, NP / E / xs] TAB1 (xstable)
SEND
```

From this single description the package derives everything else:

- the pure-Python parser (`EndfParserPy`),
- the C++ reading *and* writing code of the fast backend
  (`EndfParserCpp`), generated by a compiler included in the package,
- the structure of the Python dictionaries you work with: the variable
  names in the recipe are the keys in the dictionary, so the formats
  manual directly documents the data you get. The recipe files also
  carry the manual's variable descriptions as comments, making them
  readable documentation of the format itself.

Because the parsers, the writer and the dictionary layout all derive
from the same recipe, they are consistent with each other and with the
format description by construction.

The recipes are ordinary data, and the same machinery is open to you:
custom or extended formats — special NJOY output, laboratory-internal
conventions, format extensions — can be described as recipes and used
directly with `EndfParserPy`, and a recipe can be compiled into a
dedicated fast C++ parser module with a documented procedure. See
[format extensions](https://endf-parserpy.readthedocs.io/en/latest/guide/format_extensions.html)
and
[accelerated parsing and writing](https://endf-parserpy.readthedocs.io/en/latest/guide/accelerated_parsing_and_writing.html)
in the documentation.


## Performance

With the C++ backend and `array_type="numpy"`, `endf-parserpy` reads
the complete neutron sublibrary of ENDF/B-VIII.1 — 558 files, 1.3 GB —
in about 2 seconds and writes it back to ENDF-6 text in about
8 seconds (single core of an Intel Core i7-1165G7 laptop, warm file
cache; measured on the development version of November 2026). Every
value is fully interpreted during parsing, and written output is
formatted field by field.

The numbers are produced with
[`tools/benchmark_throughput.py`](tools/benchmark_throughput.py) and
refreshed for each release.
